The kernel is the harness. The prompt is just the ABI.

One function lives in an IPython heap. It does not RPC tools. It emits a tiny XML dialect. Parsers for that dialect are objects in the same heap — so the agent can grow its own appendages.

The hard part is not XML. The hard part is view(): unbounded heap → bounded window. If the agent can rewrite view(), it governs what it is allowed to remember.

One inference step

1
project

view() builds the prompt from ABI + live tag index + pins + last N cells. Not the whole In[].

2
complete

Speech is text. Syscalls are XML blocks. No native tool-calling schema.

3
scan

Fence-aware lexer, not a real XML parser. Payloads can contain </python>.

4
dispatch

Builtins locked. Unknown tag → handlers[tag](body, **attrs). Result lands in the heap and the log.

5
stop or recurse

No tags / <done/> → speak. Else frozen step() loops. Agent does not rewrite the loop.

Minimal prompt is an index, not a manual. Static text is the ABI (~25 lines). Every turn also injects tags: python, bash, register, pin, grep? and the pin names. Capability grows in the heap; the prompt stays a table of contents.

Freeze this, or the creature eats itself

Let it write

  • new tags
  • view()
  • pins / notes
  • stop hints

Do not let it write

  • the scanner
  • step() itself
  • python / bash / register
  • exec policy

Will still bite you

  • empty ABI wastes turns reinventing grep
  • view() dumps too much or forgets tags
  • handlers rot across a long session
  • kernel python is full user RCE
